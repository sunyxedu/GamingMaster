# Candidate 0002: admit only reasoning calls that fit

Implementation parent: `0001`. The error-free leaderboard incumbent remains `0000-tier1_astra_naive`. This is one conservative reliability experiment; no game evaluation or model backend was run during construction.

The archive supports preserving 0001's gameplay machinery. Its `eval.json` records scores **6, 4, 3**, compared with the incumbent's **1, 0, 0**. The baseline's seed-1 trace, line 3, contains the response **`click 19 20`**, immediately followed by a step with **`"action": "noop"`**. Across its three traces, all 24 click responses become noops. In both zero-score baseline episodes, all 40 observation prompts truncate the matrix. Candidate 0001 repairs these interface failures and gets substantially farther; its zero-error exclusion is a separate problem from its observed scores.

The concrete failure in 0001 is deadline admission. Both unsuccessful episodes end with **`harness did not return within 899.99...s (episode deadline)`**. The adaptor describes unlimited game wall time, but the evaluation manifest independently specifies **`"max_wall_s": 900.0`**. The parent checks only whether remaining time is positive, then calls `ctx.think` with its default 300-second timeout.

In `../0001/trace_seed1.jsonl`, line 456, request 36 starts at clock **896.2652931213379** with **`"wall_s": 3.7656729221343994`**. There is no corresponding completed model call. Its preceding call took **31.893118143081665 seconds**. In `../0001/trace_seed2.jsonl`, line 644, request 32 starts at **863.3689019680023**, with **`"wall_s": 36.6256148815155`**; again no completed response precedes the deadline error. Just two completed calls earlier, latency was **50.40928387641907 seconds**. Neither failure is evidence of an action-parser crash or an exhausted 40-call allowance.

**Hypothesis:** 0001 already supplies a useful observation/evidence/planning loop, but admits reasoning work that cannot reliably finish inside the evaluator's remaining wall budget. Reserving measured inference time and return time should make its scores eligible without sacrificing levels already reached. This iteration tests resource scheduling, not improved puzzle inference. It deliberately retains the parent's prompt, evidence retrieval, batching limits, and exploration policy so a large policy change does not obscure the repair.

The new module adds a `Deadline` controller. Before prompt preparation and immediately before inference, it requires more than **10 + max(60, 1.5 × the longest completed call in this episode)** seconds remaining. The 60-second initial allowance exceeds the approximately 51-second maximum observed in the parent; the multiplier responds to slower calls during a new episode. These are scheduling priors, not game rules or guaranteed model latency bounds. It obtains the actual time limit from `ctx.budget.remaining()`, reconciles it with `ctx.clock.now()`, and never embeds the archive's 900-second episode duration. Missing, null, or infinite wall limits remain unbounded.

Each admitted call receives `timeout_s=min(300, remaining_seconds-10)`. A literal standard-library `TimeoutError` ends the episode cleanly with a trace event. Every specialized exception propagates, including `ModelUnavailable`, even if it subclasses `TimeoutError`. The harness uses no worker threads or background inference. It checks time before every action and applies the 10,000-request ceiling inside batches as well as outside them. A deadline stop returns without spending requests on noops, resets, or unsupported exploration.

Three defensive parsing fixes accompany that scheduling change: JSON recovery is bounded to 100,000 characters and 64 decoding attempts; oversized nonliteral action strings are rejected before integer conversion; a recovery rule's path must be a string before dictionary lookup. These address malformed stand-in output, not the observed live timeout errors. Arbitrary coordinates under the advertised click grammar remain accepted. Local invalid-input recovery remains capped at three rejected requests.

The inherited architecture remains complete and general:

- Discover grids structurally, transmit lossless coordinate bands plus all other observation fields, and attach a supplied current image. Connected components offer occupied-pixel click representatives without assigning semantic roles.
- Store up to 256 measured transitions, 16 salient events, state/action attempts, action-effect counts, visited visible states, and an episode-local model notebook. Retrieve the last batch, 12 recent events, salient evidence, current-state attempts, current maps, and the notebook in a fresh Astra session. There is no cross-episode answer cache.
- Astra infers schema paths, controls, rules, goals, and plans. Code validates current legal forms before each actual action. Execute mode permits 32 actions; probe mode permits eight candidates and stops at the first effect. Repetition is capped at 16 per entry.
- Check supplied pixel, metadata, and change predictions after every step. Cancel on refutation, score/phase/action-set change, recovery state, reset, or stalls/loops. Record actual submitted actions and counterexamples. Retain inferred mechanics across levels while re-reading the board.
- Only malformed or noop-only plans invoke cheap exploration: least-tested legal actions in the current visible state, component click points, then coarse spatial coverage. There is no game-specific simulator, assumed inverse, predetermined opening, Jev call, or hidden-state access.

Verification used the prescribed Python 3.14 interpreter. All **12 short unittest cases** in `test_harness.py` pass, covering insufficient time, adaptive reserve, an unexpected slow call, stale budget snapshots, unlimited time, malformed output, click grammar, renamed fields, mutable observations, prediction/progress interruption, per-action time checks, fresh episode memory, and exception propagation. One fixture initially made the baseline's own mistake of checking clicks only against literal action names; the fixture now validates the parameterized grammar. No policy behavior was changed to satisfy that faulty assertion.

A read-only timing replay applies the admission calculation to the parent's already-recorded request clocks and latencies. It admits all **29** seed-0 calls, whose archived final score is **6**. It stops before seed-1 request **34** at clock **843.229**, when archived score is already **4**, and before seed-2 request **31** at **841.701**, when score is already **3**. Thus those fixed histories would retain all 13 observed levels while admitting 92 rather than 97 calls. This is a scheduling counterfactual, not an evaluated candidate score: fresh model outputs and latencies may differ.

**Confirmation:** the real evaluator reports no episode deadline errors, retained mean levels near or above 0001's observed 4.333, and fewer late calls. At minimum, the candidate must outperform the eligible baseline's 0.333 without errors. Trace events should show either normal completion, call-budget exhaustion, or an explicit deadline/timeout stop with score preserved. Fewer calls breaks score ties.

**Refutation or narrowing:** deadline errors persist despite bounded inference timeouts, or early admission stops materially reduce completed levels. The former would require examining the runner/backend's timeout behavior rather than inventing puzzle rules; the latter would argue for better use of the final time window. If the scores remain 6/4/3 with clean returns, regard this as a successful reliability repair, not evidence that rule composition improved. Late prompts still grow to roughly 44–65 KB and both hard episodes report prediction refutations; compact evidence retrieval and stronger learned models remain possible later experiments.

Limits: synchronous game actions cannot be preempted, and a backend that ignores `timeout_s` can still exceed a deadline. Only literal `TimeoutError` is treated as a recoverable timeout; other backend exceptions intentionally propagate. Conservative admission can leave useful time unused. Visible-state aliasing, model-selected schema mistakes, unprocessed animation artifacts, and duplicate evidence in prompts remain inherited limitations. No official pre-flight, live game run, held-out result, or source inspection was performed.
