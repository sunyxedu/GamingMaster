# 0021 — Route portfolio with a no-route recovery interlock

**Parents:** `0017` and `0019`. I retain 0017's high-throughput complete-home portfolio, through-bank/row-7 road launch, auxiliary and matched-home filters, and neutral-rearmed motor. I take 0019's important idea that an observed same-row actor should be handled at the motor boundary rather than only by long-horizon route ranking, but change where it is applied.

## Hypothesis and evidence

The remaining failure is not simply that a route picked the wrong margin. In 0017 seed 127, the loss at tick 16280 has frog row 8/x100 on a safe-looking shape-184 turtle, actor row 8/x108, and the last plan is `NOOP` from x93 with margin 3.5. The same trace loses at tick 22094 at x148 with actor x132 and at tick 26514 at x100/x108; seed 101 has the same row-8 actor/support pattern at ticks 42866, 43804, 44841 and 45724. The frog is carried (`moving_with_platform=true`, `hazard_e7=128`) immediately before each loss and becomes unsupported on the next frame. Thus a positive route certificate and a current actor overlay do not by themselves supply an executable exit.

0019 confirms the missing boundary case. Its actor escape runs when a route exists, but its worst traces still lose at seed 107 ticks 20444/21084 (row 8, x154/155, actor x138/140) and seed 109 ticks 15893, 47467, 48745 and 51860 near the carried edge. More importantly, both parents can fall through to a passive `NOOP` when the actor overlay makes the current row look blocked or when no complete route is returned. A passive fallback is exactly the dangerous action for a carried frog whose support/actor forecast has just become invalid. The 0019 target hysteresis itself lowered throughput (42.5 versus 0017's 53 homes), so this candidate does not impose that long commitment lease.

**Testable hypothesis:** make recovery a separate, short-horizon motor mode. Whenever the current route is empty, the selected route is a passive wait, and a carried frog has an E7-high same-row actor whose predicted gap is at most 17 pixels, or outward drift forecast toward the edge, search an actor-free but support-checked one-hop escape immediately. Prefer an inward lateral move at an edge, otherwise a supported vertical row exit, then a lateral move that increases actor separation. This is not permission to jump into water: every escape is checked against live carrier geometry and support for the four-frame neutral release interval. It should convert the repeated `NOOP`/no-route losses into actual supported movement without globally padding the planner or changing its home portfolio.

## What changed

1. **Preserved 0017's route engine.** The separated sprite-copy intervals, measured object velocities, complete route alternatives, row-7 launch, strict median treatment, matched E3/E5 home alert, independent public auxiliary track/spawn reservation, and neutral press/release remain the normal controller. A valid complete route still wins; no target hysteresis is used.
2. **Current-carrier drift.** The field uses the measured velocity of the safe carrier that contains the frog when one can be identified, rather than averaging separated row objects. This is used only for the current row; it does not assert that a sprite decoder is perfect.
3. **Recovery field.** `Field(..., actor_overlay=False)` is used only by an emergency bridge. It removes the auxiliary's raster blockage so that code can ask whether the frog can actually move to a supported landing; it does not remove carrier, edge, row-transition, or home checks. Candidate actions are ranked by the threat: inward against outward measured drift first, supported UP/DOWN next, and then a supported lateral action away from the actor. The bridge is invoked even when route search returns no routes, which is the structural difference from both parents.
4. **Short-lived interlock.** A close same-row actor is considered before it reaches the frog, and an outward carried drift near x=140/20 is considered before the x=148 failure. If a direction is currently being pulsed, one NOOP releases the edge-triggered press; the next fresh observation recomputes the escape. The interlock never leases NOOP as an emergency and cannot be disabled by Jev or Astra.
5. **Models remain supervisory.** Jev still selects only a durable bay and a route protocol from a compact strict-JSON state. Astra reviews failure classes and emits bounded policy enums. Their answers are accepted only with agreement, probability, epoch/version and freshness checks; malformed stand-in output remains a no-op in the policy layer, not an action.

## Confirmation and refutation

Confirm if recovery events are followed by observed row/position movement and fewer carrier losses at row 8/x100 and x>=148, while route counts, no-route stalls, homes per life and time bonus remain close to 0017. A trigger count alone is not success; the trace should show `recovery_escape` followed by a non-death crossing or a later, distinct failure. Refute if actor-free recovery frequently lands in water, if the interlock repeatedly oscillates on broad safe carriers, if it causes no-route stalls/timeouts, or if deaths and homes regress toward 0019.

## Tier-2 System-1 contract

The state sent on every asynchronous request is a small JSON object:

- `game`, `phase`, and the current bounded `policy`;
- `homes`: open-bay records with `upstream_frontier`, `nearest_now`, `current_commitment`, `failed_entry_this_level`, `matched_home_alert`, and `complete_route_now`;
- `facts`: `complete_launch_exists`, `higher_level_bank_threat`, `auxiliary_on_playable_row`, `auxiliary_on_frog_row`, `auxiliary_spawn_reserved`, `target_has_matched_alert`, `urgent_timer`, and recent `entry_failed`, `bank_failed`, `repeat_entry`, and `carrier_failed`;
- `recovery`: `status` (`NONE` or `ESCAPE`), `row`, `actor_threat`, `actor_gap`, `edge_threat`, `actor`, `inward_action`, a freshness `signature`, and the code-generated support-checked candidates (action label, class, landing row and margin); and
- no raw arithmetic request: code computes intervals, velocities, comparisons and legal action strings. The epoch/version and recovery signature are also retained privately for stale-answer rejection.

The batched questions are reversed-order `Choice`s for `itinerary` and `gate`, a reversed pair for the recovery protocol over already-generated `KEEP_CODE`, `INWARD`, `FORWARD`, `BACK`, and `UNKNOWN`, and a `Noul` asking whether repeated failure evidence warrants Astra review. One Jev request is outstanding at a time, launched at most every 90 game ticks when the motor reaches a fresh planning opportunity, with a 3-second timeout. A pair is accepted only when values agree and the selected option has probability at least `.70` in both responses. A result must match the epoch, Astra policy version and recovery signature; durable advice expires after 90 ticks and recovery advice after 12 ticks. The Noul requests Astra only above `.85`. Jev never creates an action and cannot override a hard recovery interlock. If a call is late, low-confidence, malformed, stale, disagrees, or lacks probabilities, code uses the normal route or the live recovery bridge.

The fallback order is: release a held pulse if needed; take a current, support-checked recovery escape if `ESCAPE`; otherwise use the best current route (complete-home route when available, else best feasible partial route) and its current guard; then use a conservative live-guarded one-hop fallback. A passive `NOOP` is allowed only when no recovery threat is present or when no checked action exists.
