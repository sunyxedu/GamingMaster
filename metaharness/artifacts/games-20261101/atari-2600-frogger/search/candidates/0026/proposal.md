# Candidate 0026 — intent arbitration over verified routes

**Parent:** `candidates/0011/` (rewrite). The complete-route / transit planner in the strongest archive candidate 0017 and its 0023 refinement is retained as evidence about what route throughput can do; this implementation is rebuilt rather than copying that harness. It is a conservative, testable redesign of the model/code boundary, not a new margin-trigger experiment.

## Hypothesis from the archive

The bottleneck after the 0017/0023 jump is not finding homeward paths; it is repeated lethal decisions on river carriers despite positive local certificates. 0023 seed 127 records row-8/x100 with an actor at x108 dying after a `NOOP` (tick 16280); a second row-8/x100 loss at tick 26514 follows another `NOOP`, despite reported margins 3.5 and 6.5. 0023 seed 109 similarly reports x146/actor x130 at tick 36457 and x152/actor x136 at tick 37749 after no-op waits. Meanwhile 0023 seed 107's remaining carrier failures include row 9/10 losses with no auxiliary actor. Thus an actor/edge veto or larger scalar support pad is not a complete explanation. `lessons.md` also records that 0021/0022/0023 generated many “escape” or “veto” events without validating saves; an unsupported rescue action is worse than a wait.

The parent 0011's route engine already recalculated forecasts and neutral-rearmed hops, but chose a fixed local scoring policy and only learned a larger river pad after losses. The new hypothesis is that some remaining losses are *posture errors*: when the present state is still feasible, a balanced shortest-route tie-break may keep riding instead of selecting an already-certified vertical exit, or may overvalue urgent progress over wider support. A small typed intent choice can arbitrate among code-generated, freshly rechecked routes, while the hard legality and support tests remain code-owned. This is falsified if model posture changes do not change route ranking/actions, or if carrier losses persist at the same rate despite more certified vertical exits.

## What changed

- Rebuilt a finite-depth route search with explicit separated sprite copies, per-row swept road intervals, safe-carrier support intervals, measured object drift, one-hop dwell checks, open-home docking, and a small portfolio of first-hop alternatives. It still treats unknown home-crocodile status as unknown. Standard modes are pulse/rearm controlled; no direction is deliberately held across a completed hop.
- Replaced the prior goal/protocol interface with a short-lived **posture arbiter**. Code derives semantic route features (`wide/thin`, `whole route found`, progress class, destination, and committed bay), and Jev chooses PROTECT, ADVANCE, ESCAPE, ALIGN, or UNSURE. The answer changes route ranking only; every candidate must already pass the same current forecast. That is a different division of labour from asking Jev to select a durable bay itinerary and asking code to own nearly every motor decision.
- Astra is now a failure-pattern reviewer, not an occasional source of opaque route preferences. Only after at least two life-loss witnesses does it receive the prior row/carrier/plan summary and return a tiny whitelisted policy (`risk`, `road_margin`, `river_margin`). Strict parsing means prose/garbage preserves the current policy.
- All model requests are asynchronous. There is always a code-owned route while a model is late; Jev output is accepted only for matching life/home/level epoch and phase, at most 72 ticks old, agreeing under reversed option order, with selected-option probability at least 0.60. Astra changes are level/epoch checked. One Jev request is made at most every 54 ticks, and one Astra review at most every 1800 ticks.

## Jev interface and bridge

The strict-JSON state has `observation` with tick, named zone/row, platform-carry flag, x bucket, code-projected 18-tick edge bucket, diving-carrier presence, urgency bucket, level, open-bay count, current target bay, same-row actor presence, and existing intent. `candidate_routes` contains at most six code-generated alternatives with route label, first-hop label, destination class, whether the local search endpoint is reached (row 7 for a road launch or an open home for river entry), clearance bucket, action-effect class and committed bay. It does not expose raw RAM, large object tables or arithmetic as a language task.

A batched request asks two order-reversed `Choice`s over PROTECT / ADVANCE / ESCAPE / ALIGN / UNSURE and a `Noul` about explicit near-term lethal exposure. The first is an intent classifier, not a joystick generator: PROTECT raises route-margin value and discounts river waiting; ADVANCE favors short complete paths; ESCAPE gives preference to certified vertical exits and penalizes NOOP; ALIGN rewards the current open-bay commitment. A returned Noul threat can request Astra review once repeated loss evidence already exists. The two choices must agree; the selected key must have probability >=0.60 in both. Answers are discarded after 72 ticks, a life/home/level change, or road/river phase change. Missing probabilities, low confidence distribution, malformed response, or timeout leaves BALANCED unchanged.

Astra is sent at most three compact failure witnesses, with no seed-specific route instructions. Its only valid outputs are the listed enums. `conservative` affects ranking; `wide` expands the relevant road/carrier exclusion margin. The normal calibrated values are restored only if Astra explicitly requests `standard`; invalid or late results are ignored.

## Fallback and evaluation criteria

The current observation is searched every motor decision; the model is never awaited. The fallback ranks only currently certified alternatives under BALANCED or Astra's compiled policy; if no complete path exists, it uses the best certified progress/survival alternative, and if none exists it posts NOOP. A fresh posture cannot make an unsafe landing legal. Model futures catch ordinary timeout/runtime/parse errors; budget exhaustion and episode closure follow the contract.

Confirm the hypothesis if Jev postures measurably change the selected first hop in otherwise close certified alternatives, `ESCAPE`/`PROTECT` lowers later river deaths (including no-actor row-9/10 deaths), and homes per episode stay near the 0017/0023 range without raising stale ticks or model errors. Refute it if posture acceptance is rare or changes only telemetry, if deaths remain concentrated on the same supported-looking waits, or if conservative/escape ranking costs more completed homes than the life-preservation gain. In particular, count witnessed subsequent survival, not just posture/override events.
