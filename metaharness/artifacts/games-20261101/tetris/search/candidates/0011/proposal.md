# Candidate 0011 — move the placement search off the tick loop

## Parent and diagnosis

Parent: `candidates/0007/` (the 0004/0003 crossover). I kept its code-owned SRS-shaped placement search, one-preview evaluation, verified executor, Jev bridge, and asynchronous Astra policy reviewer.

0007 is the best candidate at **50,094** mean score: it placed 200 pieces, averaged 78.33 lines, had no illegal actions, and reduced stale ticks to 29.5%. Its remaining worst-episode symptom is a clock-boundary stall, not bad model parsing. In `trace_seed0.jsonl`, after the first lock at tick 6, the harness posts a fresh `noop` at tick 7 and then the world records stale `noop` at ticks **8, 9, 10, and 11** before the next `left` at tick 12. The same pattern is visible in the lower-scoring seed 4: after tick 24, the trace has a fresh `noop` at tick 25 followed by stale `noop` ticks **26–29**; after tick 33, it has a fresh `noop` at tick 34 followed by stale `noop` ticks **35–38**. The lesson records the same representative spans as ticks 26–29, 35–38, and 147–150.

Those spans occur immediately after 0007's new-piece branch posts `noop` and synchronously runs `_plans()`. The parent’s one-ply lookahead enumerates the next piece for every shortlist candidate, so it can consume multiple 50 ms ticks. The stale actions are therefore not evidence that Jev selected a bad primitive action: no fresh action is posted while code is doing its own search.

## Hypothesis

**If code-owned placement search is launched in the background and the clock loop posts a fresh safe action on every tick while it is pending, then 0007's placement quality will be retained while its stale-tick penalty is removed.** The search result must be tagged with `(pieces, active.type)` and discarded if the falling piece has changed. A lock deadline must never wait for the worker: if the piece is grounded or its lock grace is nearly exhausted, hard-drop the cheap emergency target.

This isolates timing/search scheduling. It does not change the evaluator weights, candidate descriptions, Jev questions, Astra policy vocabulary, or the SRS geometry.

## What changed

* `_plans(snapshot, style)` now runs in one `ctx.spawn` worker. Only one placement worker is allowed; the snapshot and piece identity are retained so a late result cannot control a new piece.
* While that worker is pending, the loop posts a **fresh `noop` each tick**, rather than posting one noop and allowing it to repeat. Near lock, it posts `hard_drop` using a zero-search current-piece/orientation/x emergency plan.
* The emergency plan is also used if a worker fails or if a Jev-selected plan becomes incompatible. The old synchronous `_best_current()` rebuild was removed from this clock path.
* Search results are harvested without waiting, adopted only for the same falling piece, and logged as `search_ready`. At episode end the finite search worker gets a short bounded chance to finish; model futures are not joined.
* Once a shortlist exists, execution and Jev/Astra behavior remain the parent behavior: one verified rotation or horizontal move per tick, then hard drop; hold is rechecked against `can_hold` and active type.

## System-1 interface and control policy

The Jev state remains a compact strict-JSON object:

```text
{
  ruleset,
  policy: BALANCED | RECOVER | WELL,
  piece_instance,
  board: {
    height: low | moderate | high | critical,
    holes: hole-free | few shallow holes | several holes | many or deep holes,
    surface: flat | uneven | rough,
    lines, level, combo: active | inactive, back_to_back
  },
  active_piece: {type, orientation, anchor_x},
  hold, can_hold, next_queue,
  fallback: C0,
  candidates: {C0: description, ...}
}
```

Candidates are generated by code and describe source (current/hold), orientation,
anchor, clear kind, projected height/hole/surface buckets, and well depth. Jev never
counts cells, performs arithmetic, invents SRS kicks, or emits keypresses.

One `ctx.decide` request batches two independent `Choice` questions:

* `pick_a`: choose the safest low, flat, hole-free candidate, preferring a clear that does not create danger;
* `pick_b`: the same judgment with the candidate order reversed, to reduce first-option bias.

The answer is accepted only when both values are valid candidate labels, equal each
other, and each selected label has probability at least **0.30**. Confidence is not
used as a probability. Timeout, ordinary failure, malformed stand-in output,
low probability, disagreement, stale piece identity, or failed hold/type validation
leaves the code fallback in control. While search is pending, no Jev request is
launched and the fresh-noop/emergency policy is used. A late answer is never applied
to a different `(pieces, active.type)` pair.

Astra remains one asynchronous policy-review call, returning only `BALANCED`,
`RECOVER`, or `WELL`; it changes future code weights but never supplies an action.

## Confirmation or refutation

The hypothesis is supported if the evaluator shows stale ticks materially below
0007's 29.5% while retaining approximately 200 pieces, its line-clear rate and
score, and zero illegal actions. Traces should show `search_ready` followed by
fresh actions, with no multi-tick stale-noop spans after locks.

It is refuted if stale spans remain despite a completed worker, if search workers
cause contract/background errors, or if urgent fallback drops make episodes top
out substantially earlier or reduce score/lines. If score stays stable but stale
ticks fall, that confirms the targeted timing hypothesis even if Jev remains only
an advisory tie-breaker.
