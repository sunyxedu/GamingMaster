Hypothesis: the apparent strategic failure of the baseline is primarily a protocol/parser failure, not weak duel planning. In the archived seed-1101 trace Astra repeatedly returned the exact legal-looking string `choose r1p1 1`, but every posted trace action is only `choose`; the baseline calls `parse_action(res.text, names)` with `names = action_spec.names`, so the prompt token and index are discarded. The observation therefore remains on token `r1p1` until the response deadline, and the final duel result is an agent-response forfeit. The same repeated-token pattern appears in seeds 1102, 1103, 1104, 1105, and 1106; the leaderboard reports 2.67 completed duels, zero native completions, and 2.67 forfeits per episode.

What changed versus the parent: the harness now reads exact actions from `observation.prompt.choices` (and constructs constrained select/order actions from the displayed candidates), then validates Astra's text against the current token before calling `ctx.act`. It uses a compact state view that retains turn, seat, LP/zones, board, chain, recent events, and the prompt while omitting the repeated static catalogue. Astra is asked for one exact legal action with a short tactical objective. Singleton prompts bypass System-2, malformed/timeout/budget-exhausted calls fall back to a legal scored action, and a stale-action retry chooses a different current legal option. Session continuity is retained for planning context, while all exceptions allowed by the contract are contained.

Evidence that would confirm the hypothesis: traces should show prompt tokens advancing after each action, no repeated `last_action_error`, native duel completions, and a sharp reduction from roughly 30 System-2 calls per duel to at most the 40-call episode budget. If the parser fix yields native completions but losses remain, the next iteration should inspect Astra's tactical choices; if forfeits or stale prompts persist, the prompt-shape/action extraction needs further repair.
