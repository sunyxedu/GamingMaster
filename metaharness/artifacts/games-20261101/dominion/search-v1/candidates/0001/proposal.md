Hypothesis: the leader fails primarily because its unit of deliberation is one UI prompt, and its generic action parser silently corrupts multi-card choices. Moving Astra to reusable acquisition plans and implementing exact local prompt execution should complete games, restore effective thinning, and improve final VP margin within the same budget.

Concrete archive evidence: all six leader episodes ended at the 1800-second deadline without game completion. In trace_seed1301.jsonl, line 15 returns `choose 5 0 1 2 3` for a Chapel hand containing Copper and three Estates, but line 16 posts only `choose 5 0`. Line 30 returns valid JSON with four IDs; line 31 posts bare `choose` and gets an error. Line 33 then spends 242.3 seconds returning another four-ID response, of which line 34 executes only one ID. A Sentry discard pass at line 87 costs 224.9 seconds. The run ends on own turn 13, at -14 VP. Seed 1200 has the same multi-selection loss (lines 15/16 and 30/31), reaching only turn 7 at deadline. These are harness failures rather than evidence against Chapel or Sentry strategy.

Change: Astra receives a compact fresh public-state snapshot, exact card rules, public ownership, computed composition, recent acquisitions and its previous plan. At most ten calls, normally every three own turns, return a strictly validated declarative target deck, scoring thresholds and optional current purchase. Targets are ordered affordable acquisition priorities with absolute ownership caps, rechecked against every new prompt. No future option IDs are reused. All prompt selection, multi-card trash/discard, reaction, action ordering and constrained gain execution is local. Chapel and Sentry preserve a configurable total-money floor. Forced discards search retained hand combinations. A bounded basket search computes Gardens, VP, pile depletion and turn-count ties before taking a winning ending. Losing single-gain endings are filtered when alternatives exist. Every posted selection is validated against the current prompt's IDs and min/max.

Calls use fresh sessions, requested 125-second model timeouts, a separate 150-second Future.result wait bound, and a 120-second execution reserve. Planning stops after two returned backend failures or one still-pending call abandoned at the wait bound. Failed or malformed plans retain the legal deterministic baseline. Only ctx.think runs in a ctx.spawn future; if abandoned, the game finishes locally and the evaluator cancels that model call on episode close. There is no other background work. Code does not read simulator internals, files or hidden information during play; standard library only. All inference goes through ctx.

Confirmation: completed games with zero illegal actions, correct multi-card thinning, substantially fewer model calls per decision, and improved actual terminal margin. Refutation: games complete but lose on deck balance, action sequencing or stale three-turn policies; the acquisition and prompt traces can identify which. This tests a structural planner/executor split plus repair of an independently observed parser defect, not a claim that the local heuristics are optimal. Bounded ending search is exhaustive only within its six-buy/12,000-node cap and candidate card set.

Validation so far: pre-flight PASS, completed game at +12 VP in 30 actions, no reported error. Its short wall budget deliberately bypassed planning, so this is a legality/fallback check, not model-policy validation. `python3 candidates/0001/check_policy.py` passes 140 archived public observations across seven valid/malformed/failed planner response classes, plus regression checks for four-card Chapel trashing, whole-turn Province+Duchy purchase endings, Gardens arithmetic, turns-started tiebreaks, and Militia discards.
