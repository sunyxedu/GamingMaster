Hypothesis: candidate 0003 loses score because its Astra action prefixes are still speculative in partially observed rooms; when a prefix is wrong, several actions are spent before a new call. The archive shows this on the weak GoToRedBall episode (seed 6): four Astra calls and a 20-action route scored 0.71875, while candidate 0002 solved the same family with a verified map controller and no model calls on an easier seed. A second, separate source of avoidable latency is candidate 0002's exact mission compiler: on MultiRoom seed 3 it escalated the unambiguous “traverse the rooms to get to the goal” mission to two Astra calls, then completed in eight actions for 0.82.

This proposal tests a semantic compilation hypothesis rather than increasing batch length. It derives from 0003 but replaces its model-produced action prefixes with the verified observation-only belief search from 0002. The compiler now recognizes generic goal missions for the audited MiniGrid MultiRoom family (and other MiniGrid wrappers whose mission mentions only a goal). Code maintains an initial-frame egocentric map, preserves unknown cells, searches over position and heading, opens doors only with legal key evidence, and chooses shortest observed routes or information frontiers. Every action is checked against the returned observation and `ctx.progress()`; a discrepancy clears the route and sends concrete evidence to Astra. Astra remains an exception planner for unsupported compositions, map contradictions, and genuinely ambiguous instructions, with bounded calls and garbage-safe JSON parsing.

The change should reduce both model latency and route regret on MultiRoom while retaining recovery on unseen layouts. It does not select a seed, inspect hidden state, or assume a fixed room geometry: the generic compiler only supplies the typed goal predicate, and all movement comes from the observed map. Relative BabyAI descriptions continue to use the initial reference frame.

Evidence that would confirm the hypothesis: MultiRoom episodes finish with zero or one Astra call, fewer actions than the prior two-call route, and no increase in rejected actions; GoTo/Pickup families preserve the 0002 success rate despite avoiding stale multi-action prefixes. Evidence against it: generic goal compilation gets stuck at an unobserved branch or misreads a goal verifier, while Astra prefix execution would have succeeded; repeated frontier cycling, pose-alignment discrepancies, or a lower success rate on BabyAI would show that the map compiler is too conservative or that the parent’s batching was necessary.

Validation target: preflight must survive arbitrary stand-in model text, and the evaluator should compare per-family success, steps, and System-2 calls on unseen seeds.
