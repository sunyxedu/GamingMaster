What changed vs. the parent: this harness first runs a conservative BFS over the symbolic observation when there is one controlled object and an already-active goal.  It treats walls, word tiles, and other physical objects as obstacles, so it does not assume push or collision semantics.  Otherwise Astra receives the full current observation plus progress and recent action evidence and returns `PLAN: ...` with at most eight primitive actions.  The parser accepts only an explicit plan marker (or an exact single action), avoiding garbage-output crashes.  Each queued action is posted separately; after every action the harness compares the logical observation and calls `ctx.progress()`.  A rejected action or a non-moving directional action clears the stale queue and forces replanning.  Model failures are caught and eventually yield a harmless wait so preflight and deadline shutdown remain clean.

Evidence that would confirm the hypothesis: difficult training or validation episodes should solve with fewer Astra calls and fewer deadline terminations, while simple active-goal episodes should solve through the BFS without any model call. Evidence that would refute it: Astra cannot reliably emit parseable batches, batched actions cross a rule-change boundary and cause more dead ends than the leader, or the conservative walker fails because physical objects must be pushed to reach ordinary goals.  In that case the useful part to retain is the progress-based queue invalidation and explicit recovery prompt, while reducing batch length.
