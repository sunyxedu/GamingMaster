Hypothesis: a model cannot compensate for missing state, and even a corrected observation is not enough when each hallway step costs a minute. A reusable, closed-loop explorer with sparse tactical consultation should convert the existing action budget into hundreds of meaningful game turns. This is a fresh controller, not a refinement of the naive one-action model policy.

Archive evidence: every initial baseline model_request is 8,450 characters and its observation ends inside the glyph array with `…(truncated)`. None contains the `map`, `stats`, or `message` fields. The complete final_obs in seed 1106 says `In what direction?` at game time 5 after 11 posted actions; seed 1101 remains at its initial coordinates at game time 3 after eight actions; seed 1104 reports `Unknown command '^M'.` The worst action-throughput run, seed 1102, spends its deadline on six actions and reaches only game time 6. All eight scores are zero, so structural changes are better motivated than latency parameter tuning.

Implementation: code owns per-level map memory, legal routes, explored frontiers, failed edges, bounded hidden-door searches, prompt transactions, stair discovery, gold collection, food availability, pet exclusion, local combat, and regeneration. It executes one action and verifies the next observation, without a model call on ordinary steps. Astra receives named stats/messages first, a coordinate-labelled ASCII map, inventory letters, monsters/pets, and a short outcome log. It may change exploration/descent policy, nominate a route destination, classify threats, or provide a short immediate action list. Calls are sparse and bounded; failures are caught and fall back to the controller. The model has no seed identifier or special access. No game implementation or external bot is used.

Observation-grounded priors: archived pets consistently have specials bit 8, and the statue in seed 1108 has bit 32; these distinguish pets/statues from threats. Archived brown `-` doors differ from gray walls. Movement failure, turn advancement, door text, hunger and HP validate the operating assumptions at runtime. The restricted keyboard is respected: inventory letters are usable only if represented by an exposed action. Arbitrary Python or new commands from model replies are never executed.

Confirm if: more actions advance game time, reachable gold/stairs are obtained, weak seeds improve above zero, and model calls decrease per unit score. Refute if: autonomous exploration repeatedly stalls, the prompt layer consumes commands without turns, or avoidable combat/starvation erases gains. Primary risks are incomplete hidden-door search, limited inventory input keys, and imperfect monster identification; these are logged separately from model failures.

Validation: pending pre-flight and dev evaluation. Any refinements and their evidence will be recorded here.
