# 0003 — Deliver a controller before asking for a complete strategy

Parent: `0002`. One candidate; no game evaluation or model-backend calls were run.

## Hypothesis

The parent's main failure is **failure to deliver an executable Astra artifact**, not a demonstrated defect in its proposed compiled strategy. Its large first compilation task always exceeded the 45-second deadline. Meanwhile the temporary greedy reflex collected rewards until it trapped itself. Smaller staged deliverables, a longer compilation allowance, and temporary preservation of maneuvering room should let the compiled architecture actually run. A second compilation can then improve long-term progress without interrupting local control.

This is a repair of the failed synthesis path, not an embedded Snake solver. It deliberately retains most of the parent's executor, compiler guard and semantic binding so the deployment hypothesis remains interpretable. The experiment bundles staging with a temporary holding policy and deadline changes; it cannot isolate their individual effects.

## Changes from the parent

1. **Acquire first, improve second.** The first Astra request asks for a 40–70-line local controller: exact immediate rules, score-seeking decisions, cheap escape checks, and deterministic predictions. It explicitly postpones an elaborate global solver. An injected `decision(action, facts, goal, assumptions, regime, expect)` helper expands the common one-strategy return schema. After installation, a second request asks for a complete stronger controller, including a progress invariant and safe shortcuts only when the public rules support them. The installed controller runs during this request. Replacements must work on the current observation, not their old prompt snapshot.
2. **Preserve a simple configuration during acquisition.** The parent's optional grid/chain bootstrap retains its runtime semantic binding and conservative occupancy checks. Before any usable controller arrives, it prefers an immediately legal non-target cell, then reachable area, then continuing its last heading. It temporarily avoids growth-inducing rewards in this game rather than growing a tangled configuration while waiting. This is a heuristic, not a safety guarantee. Once compilation attempts or budget are exhausted, it resumes the parent's target-seeking ranking instead of withholding rewards indefinitely. Unsupported geometries use the declared noop; they do not acquire a game-specific solver.
3. **Allow synthesis to finish.** Acquisition has a **120-second** timeout; improvement has **180 seconds**, both capped by remaining wall budget. At most four Astra calls are requested, with at least ten seconds between starts. The normal path uses two. These are experimental allowances, not measured candidate latencies. The 900-second episode budget still makes synthesis time and travel efficiency consequential.
4. **Separate operational failures from code failures.** A failed inference logs `compilation_no_artifact` and is retried without running the compiler on empty text. Malformed returned source still produces `policy_rejected`. A rejected upgrade retains the working controller. A contradicted prediction or execution failure disables the controller and clears its cached action before falling back.
5. **Make actual use observable.** `policy_installed` includes stage, tick, score and source size. `astra_controller_first_action` records the first executed action for each version and whether it differs from the contemporaneous bootstrap action. `controller_end` includes action-source counts and the final public observation. Existing worker events record measured wall latency. Late answers never post directly, and all spawned futures are joined before return, including on `ModelUnavailable`, which propagates.

The compiler still accepts only function-definition modules with restricted builtins, no imports/context access/private attributes, and a 25 ms / 60,000 trace-event invocation guard. This is not a security sandbox or hard preemption of native operations. Generated safety flags remain claims from generated code, not independently proven certificates. Installation performs a dry run on the current observation with discarded trial memory. Deterministic next-field predictions are checked only across one observed tick; skipped ticks discard that comparison.

## Jev state, questions and control bridge

Jev sees explicit context on every request; it does not inherit Astra's conversation. Runtime Astra receives the bundled `usage_guide()` when designing or revising the generated interface.

**Initial binding state:** `rules`, action-name-to-description mapping, `noop`, action notes and the actual observation. Five independent Choice questions identify the zero-based x/y extents, head-first occupied trail, desirable target, and support for the complete geometric assumptions. Options are generated from observed value shapes with an explicit unknown option. No observation-field name or directional action identifier is hard-coded. Binding requires selected probability **>=0.65**, non-null confidence **>=0.2**, and structural checks. Observed one-step head motion tests the binding. These are inherited, uncalibrated thresholds.

**Review state:** the same public rules/actions plus current observation, `plan_version`, generated `goal`, `preconditions`, computed `facts`, described `candidates`, current `default`, and five recent tick/score/action/facts records. Reviews run asynchronously at most once per **32 ticks**, with at most one outstanding Jev call.

- **Audit:** keep, revise, or unknown. The question asks whether supplied evidence supports the assumptions and a score-progress strategy. Ordinary travel is not by itself a failure. A revise answer requires probability **>=0.75**, confidence **>=0.2**, matching controller version/regime and age at most **20 request ticks**. It requests an Astra replacement while the current controller continues.
- **Strategy:** asked only when there are at least two currently safe strategies. It uses Astra's focused English question, candidate descriptions and computed evidence. Accepted probability **>=0.65** and confidence **>=0.2** create a strategy-ID lease for at most **20 ticks from the request**. Code recomputes that strategy's action on every current observation and requires the same version/regime and a currently safe candidate. Unknown, absent confidence, expired leases or missing candidates retain the current local default. `jev_changes_action` logs an actual directional/action change, not merely a fresh answer.

Astra also revises after parsing/execution failures, deterministic prediction contradictions, or 256 ticks without score change once at least 60 seconds have passed since a compilation request. The hypothesis is that semantic review should change the reusable interface when its assumptions or progress evidence fail, while code continues handling exact state transitions and deadlines. No model answer is treated as a delayed next-tick action.

## Generality, risks and decisive evaluation evidence

The submitted executable contains no game-name branch, fixed game observation key, action-name mapping, stored route, precomputed completion policy or cross-episode cache. Field meanings enter through public descriptions, observed shapes and model judgments. Astra writes the actual game policy during the episode. The inherited geometric bootstrap supports only an explicitly verified class of interfaces; it is not a universal opening survival policy. The synthetic non-geometric fixture below checks contract mechanics, not held-out-game performance.

**Support:** successful acquisition and improvement artifacts appear before termination; substantial actions run under installed policies; prediction mismatches remain rare; and mean completion exceeds **0.41237** without increasing stale ticks materially. Lower deployment latency and greater survival during acquisition are intermediate evidence, not the objective. Useful Jev contribution must be visible in changed actions or evidence-driven revision events.

**Refutation:** even the smaller first deliverable times out; the holding heuristic fails or sacrifices too much wall budget; installed controllers reproduce the same greedy trap; upgrades cannot recover a moving configuration; or mean completion falls despite successful installation. In particular, merely surviving with no reward while waiting does not confirm the hypothesis. A plausible next ablation, after this single candidate is evaluated, would keep staged prompts/deadlines but restore greedy acquisition to isolate the holding policy's contribution.

## Validation performed

Syntax/import checks and short synthetic stand-in runs passed for arbitrary/empty model text, forbidden imports, runaway generated loops, acquisition followed by improvement, the compact ABI, deterministic predictions, timeout classification and retry, retaining a working controller after a failed upgrade, invalidation and cached-action reset after a prediction contradiction, an actual typed Jev strategy change, absent-confidence rejection, renamed geometric fields/actions, both models' `ModelUnavailable` propagation, and joining a worker that finishes after the synthetic episode. These checks use a tiny invented counter interface and direct helper inputs; no game implementation or held-out game was read, and no real-game or real-model performance is claimed. The evaluator's official preflight and evaluation remain outstanding.
