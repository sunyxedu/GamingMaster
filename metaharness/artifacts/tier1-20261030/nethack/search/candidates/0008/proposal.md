Hypothesis: the remaining weak-seed failures are caused by blocking Astra latency, not lack of map bookkeeping. In candidate 0006 seed 1108, the first advisory request started at game time 88 and its answer did not arrive until wall time 1174 seconds; two more requests then consumed the remaining deadline, leaving score 0 at depth 1. Seed 1101 shows the same pattern: the third request began after score 188 and ended as EpisodeOver at 1800 seconds. While a request is in flight, a turn-based game can safely continue because model latency does not advance NetHack turns. A background advisory should therefore preserve the fast deterministic expedition and apply the answer only when it is ready.

What changed vs. the parent: Astra consultations are launched through `ctx.spawn` and polled without blocking the turn loop. The controller continues verified movement, stairs, food and prompt transactions while an answer is pending. At most one advisory is in flight; completed futures are parsed with the same strict garbage-safe parser, and failed/late futures are discarded. The deterministic safety gates remain authoritative, so an unavailable answer cannot post an unsafe model action. I also cap the number of asynchronous requests and stop launching them near the deadline, retaining cycle-aware novelty routing from 0006.

Evidence that would confirm/refute it: traces should show actions and increasing unique terrain while an `advice_pending` request is outstanding, with fewer episodes ending at depth 1 and no increased S2 failure count; score and maximum depth should improve especially on seeds like 1108.
