## Hypothesis

The strongest prior (0002) fixed the fatal free-form action problem and reached a mean true VP of 7.0, but it still treats Astra as a portfolio selector that must be consulted repeatedly while code chooses the next single action. That leaves a gap between a strategic project and its execution: a road, trade, and settlement are evaluated independently, so the executor can drift toward a different project after an intervening action. Candidate 0003 shows the opposite failure: one coarse goal is too weak to commit to a funded route. The hypothesis for this slot is that a short, explicit transaction sequence gives Astra enough commitment to finish a coherent project while live legality checks keep it safe across dice, robber, and opponent changes.

The traces support this diagnosis. In 0002 seed 102, the planner prompt asks for a `project` and says code will execute it, but the model answer is still only a mode/project JSON; all subsequent decisions are generated by the local chooser. In the same trace the agent reaches only 3 true VP while opponents are already at public VP 2–3 and the agent has spent roads and a Knight. In 0003 seed 102, the policy reaches a state with 2 true VP, three roads, and one Knight, then repeatedly rolls/ends turns without a concrete funded project. These are different symptoms of the same missing transaction boundary.

## What changed vs. parent

This harness keeps 0002's verified board graph, pip production, route search, exact maritime-trade construction, postcondition checks, and bounded asynchronous Astra call. Astra now also returns at most four typed steps (`sequence`) for the selected project. The executor matches only the current legal action with the exact supplied type and parameters, consumes a step after a successful state change, and falls back to the economic compiler when a step is no longer legal. Any rejection, unchanged revision, or postcondition contradiction clears the sequence and records evidence for replanning. Setup, discards, robber choices, rolls, and end-turn remain deterministic code paths, while Astra can still select a current legal recovery action.

The prompt explicitly distinguishes advisory sequences from authoritative IDs: the model cannot invent coordinates, and every queued step is checked against the live `legal_actions` list. A sequence is discarded on failure or replaced on a later strategic call, so a contested site or resource shock cannot lock the game into a stale build order. The parent’s 210-second foreground wait and compact JSON response are retained because the archive observed a 211-second worst call and service-admission delays.

## Evidence that would confirm or refute

Confirmation would be zero or near-zero illegal actions, fewer reversals between road/trade/settlement projects, and higher minimum per-seed true VP or win rate than 0002 on the training seeds, especially when a route requires multiple roads. Refutation would be sequences becoming stale after ordinary rolls, projects starving cities because the model overcommits to roads, or no improvement despite fewer strategic reversals. The decisive check is unseen seeds: a sequence executor that relies on fixed vertex IDs or assumes a particular dice order should fail there, while one that validates each step and replans from `ctx.progress()` should generalize.
