# Settlers of Catan adaptor

`game.py` implements Tier 1 `TurnGame` using the real headless Catanatron engine in process. It reuses the `game_v1.py` integration structure (retained unchanged), with API adjustments for the stronger upstream players. No GUI, account, credentials, server, GPU, or play-time network is needed.

Catanatron is pinned to commit `ecf931181b9a65bb4116a2153fb78c16f1438e00` (September 8, 2026), package version 3.3.0, GPL-3.0-or-later. `requirements.txt` pins the upstream commit and dependencies for connected provisioning. `./setup.sh` installs offline from `runtime/wheelhouse` using SHA-256 pins in `requirements.lock`, then runs `uv pip check`. Its optional first argument overrides the evaluator Python. `CATAN_WHEELHOUSE` is optional, documented in `env.example`, and used only by setup. The complete seven-wheel wheelhouse, Catanatron license, and corresponding source archive are retained under `runtime/`. Offline setup and dependency verification succeeded.

## Opponents and measured strength

All three opponents use upstream **AlphaBetaPlayer, full depth 2, base value function, no candidate pruning, no epsilon exploration, and no wall-clock cutoff**. `StrongPlayer` selects these settings and invokes the upstream recursive search to completion. There is no random/weaker seed variant or fallback.

This is the configuration identified as best in the pinned source's `documentation/advanced/making-catanatron-stronger.md` leaderboard (80% versus ValueFunction over 25 upstream games). Depth is an unbounded integer, so there is no literal maximum setting. A depth-3 trial was stopped after several minutes without completing a game; depth 2 is the published strongest verified configuration. Removing the upstream 20-second deadline avoids partial searches and load-dependent decisions. Greater depth is not claimed to be statistically inferior. Experimental `CONTENDER_WEIGHTS` are not established as stronger than the leaderboard's base weights.

**Local measurement: 15/16 wins, 93.75%, against the previous opponent mix.** Each game seats one AlphaBeta versus one each RandomPlayer, WeightedRandomPlayer, and VictoryPointPlayer, on standard maps with seeds 901–916. AlphaBeta rotates through realized seats by `seed % 4`. These are the same policy families as `game_v1.py`, running on the newly pinned engine with isolated RNG copies; this is not a replay under the old engine. No games truncated. Mean AlphaBeta terminal true VP was 9.9375. The 95% Wilson win-rate interval is approximately 71.7–98.9%, so 16 games are evidence of improvement, not a precise population estimate. Mean elapsed time was 8.91 seconds/game during concurrent tests. Results: `runtime/benchmark_compare.jsonl`.

## Rules and interface

The engine enforces the standard 19-hex base map, snake setup, 10-VP target, discard threshold 7, maritime trades, banks, development cards and awards. Initial settlements/roads remain player decisions. Tokens use the valid `official_spiral` generator. Friendly robber and expansions are off. The engine supports domestic trade primitives, but these are not generated by the legal interface used here, so domestic trading is not exposed. Players choose each discarded resource and may play development cards before rolling. Robber hex/victim selection is combined.

Observations contain board topology, buildings/roads/ports (`ANY` = 3:1 port), public bank, own full hands and true VP, old-card availability flags, opponent hand counts/public VP, pieces remaining, awards, dice, legal choices, and up to 128 events since the previous accepted step. Events conceal opponents' purchased cards, discarded identities, and theft identities unless the controlled player is involved. Deck order and opponent true VP are never serialized. `events_truncated` marks a clipped history. Tested observations were about 16 kB, below 200 kB.

Submit an ID like `r16:a2`, or `{"id":"r16:a2"}`. IDs include the action revision and expire after an applied action. Alternative grammar: `type JSON-parameters`, e.g. `build_settlement 12`, `build_road [1,2]`, `play_monopoly "ORE"`. Parameters must match an engine-provided legal object. A bare type is accepted only if exactly one choice exists. `noop` and malformed/stale/ambiguous choices leave state unchanged; errors appear in the next observation. Each step applies one controlled action, then runs bots to the next controlled decision or termination. `describe()` supplies supported rules, costs, observation fields and action semantics.

## Scenarios and randomness

Controlled seat is the realized engine seat `seed % 4`, not a rotated color. Actual color order is reported. Train 101–104, held-out 201–204, validation 401–404 and dev 301–302 are disjoint and use identical rules/opponents/map distributions. Each main split covers all four seats. Four-seed groups keep roughly half-minute episodes manageable. Every integer seed is valid.

Catanatron uses a per-game RNG but native copies share it. `IsolatedGame.copy()` clones the RNG and legal list for every nested search copy; bot decisions also receive a copy. Sorted legal actions stabilize IDs and tie-breaking. Removing the AlphaBeta deadline prevents timing-dependent choices. Harness/global randomness cannot alter live play. Same seed plus the same action sequence replays in integration tests. Different actions may consume different draws, so policies do not necessarily see identical dice.

## Scoring and limits

`score = win + min(true_VP,10)/100`: a win outranks a loss and VP provides a smaller progress signal. Report **win rate separately as primary**, mean terminal true VP as secondary; averaging the composite is not exact lexicographic policy ranking. True VP includes hidden VP cards and awards. `info()`/`score_breakdown()` report win, true/public VP, completed normal turns, total actions and termination/truncation; `info()` also records winner, seed, engine/commit, opponents/settings, actual seats, initial map, capabilities, switches, caps and illegal-action count.

Caps are 1,000 completed normal turns or 20,000 engine actions. Setup advances are excluded from normal turns; raw engine counter is separate. Cap episodes are truncated, never wins. Engine/bot failures set `valid_trial=false` and an `invalid_reason`. Bad user input does not invalidate a trial. No game clock runs. `close()` discards state, is idempotent and owns no subprocesses/connections.

Retained upstream limitations: victory is checked for all players after each action rather than only on the winner's own turn. The base value function focuses on one enemy in some features. AlphaBeta receives full engine state and can inspect hidden hands/deck data in simulations; model observations remain filtered. Chance expansion has approximations, including uniform robber-resource branching and roll/card outcomes supplied in action values instead of the newer action-record API. These affect built-in AI estimates; actual play uses the authoritative execution path. We do not claim information-symmetric or globally optimal AI.
