Hypothesis: exhaustive all-action search spends too much work proving hypothetical deep probes, while a repeated one-step policy improvement can evaluate more root choices within the same time budget. Restrict simulated continuations to possible answers, evaluate every legal root probe against those attainable continuations, then repeat the improvement after each actual feedback. This tests search decomposition, keeping the parent's opener, public uniform answer prior, reward objective and action verification unchanged.

Evidence: the leader 0004's seed-0 trace logs 165 candidates, `diner`, reward 528 and `search_finished:false`, followed by `heron -> rerun` for a four-guess solve. Parent 0009's seed-0 trace logs 117 candidates, `denet`, a nonzero bound gap (14 in the training trace) and `exact:false`; its sequence is `soare -> denet -> reign -> rerun`. These actions pass verification. Parent seed 17 proves its continuation value yet still takes `soare -> pedal -> cheat -> tweak`, four guesses. Thus more proof alone does not imply better finite-sample score; bounded runtime and attainable-policy quality are separate questions. The hypothesis is about allocating computation broadly at each observed decision, not about favoring these particular eventual answers.

Changes versus 0009:

- Preserve `soare`, exact duplicate-aware history filtering, public-file hash checks, and uniform probabilities over surviving public answers. No seed, hidden target or private implementation is used.
- Replace recursive all-legal-action branch-and-bound with root policy improvement: all legal guesses produce candidate partitions; equivalent partitions are deduplicated; candidate-only continuations supply attainable reward for each root action.
- Continuations through 24 candidates use exact candidate-only Bellman search with memoization and upper-bound pruning. Larger branches use a complete candidate-only minimax rollout. No optimistic leaf estimate is represented as an achievable score.
- Recompute the all-legal root search after each real observation. The answer-only restriction is on the simulated tail, not on the next real action. An information probe can still be chosen on any turn, including the penultimate one.
- Retain a 150-second local limit, stop on ctx.done, and retain the best fully evaluated action. Logs distinguish root scan completion, restricted-tail search, and globally optimal search (never claimed here).
- Preserve the parent's shared action verifier and bounded Astra recovery: turn/history advancement, unchanged prior history, feedback membership, candidate reduction, rejection counters and stale observations are checked after every ordinary or recovery action. Model timeouts, garbage replies and exhausted budgets are handled. If Astra returns no usable guess, at most two consistent unused candidate fallbacks are permitted; all pass the same verifier. Persistent rejection therefore terminates even when no model-call budget remains.

Confirmation: improved mean score without errors, with more root alternatives evaluated and fewer time cutoffs than 0009, followed by generalization to unseen answers. Refutation: worse reward from systematically undervaluing multi-probe continuations, or cutoffs that still prevent broad root evaluation. A completed rollout scan is not a proof of globally optimal play, and a four-guess training branch alone does not establish a bad policy.

Validation and observations:

- Required preflight passed: five accepted guesses, score 0.333333, no errors or model calls. Stand-in inference was not reached; recovery was exercised separately.
- `checks.py` independently checked 1,000 duplicate-aware feedback pairs against a Counter-based implementation. It compared 120 small-state/horizon cases to exhaustive root-probe/candidate-tail enumeration, including the chosen action's attained value. All passed.
- Fourteen fake-context episodes/checks cover normal play, rejection, stalled observations, action exceptions, usable JSON, garbage replies, timeouts, persistent rejection and no remaining model budget. Recovery and fallback actions share the production verifier. Persistent rejection stops within three actions.
- One dev invocation, `dev/20261031-093132`, solved both seeds in four and three guesses, mean 0.583333, with zero errors, zero failed calls, zero model calls and no verification failures. Digest, eval.json and traces were read. The paths were `soare -> butch -> bobby -> bongo` and `soare -> cutin -> tumor`. The 87-answer state evaluated 1,718 root alternatives and attained restricted-policy reward 276; the 59-answer state evaluated 253 and attained 194. Both scans completed. Parent all-action proof values were 282 and 196: cheaper completed search does not imply an equally strong planned continuation.
